# full-video-motion-workflow

一个面向中文真人口播视频的完整 AI 剪辑工作流 Skill。它把整条视频当作连续的视觉段落来规划：先理解 A-roll、素材和口播，再用 HyperFrames / Remotion 制作可独立调整的动效与转场，最后在 ChatCut 中完成组装、混音、检查和交付。

## 一句话安装

在终端执行下面这一句，Skill 会安装到 Codex 的 Skills 目录：

```bash
curl -fsSL https://raw.githubusercontent.com/xiaoshan-shuma/full-video-motion-workflow/main/install.sh | bash
```

安装完成后重启或刷新 Codex，然后直接说：

```text
使用 full-video-motion-workflow，采用奶油拼贴风。
```

也可以手动安装：

```bash
git clone https://github.com/xiaoshan-shuma/full-video-motion-workflow.git \
  ~/.codex/skills/full-video-motion-workflow
```

## 适用场景

- 中文口播、教程、AI 工具介绍、产品讲解和个人品牌视频
- 需要完整分镜、动效、B-roll、转场、音效和 BGM 的成片
- 希望保留人物主体、已有字幕、原配音和可编辑时间线的 ChatCut 项目
- 需要把透明 WebM / ProRes 动效叠加到人物画面，而不是把所有效果烙成一个大视频

## 两种视觉风格

本 Skill 内置两套可以独立使用的视觉系统。每次制作前先选定一套，并在 scene-plan.json 和 style-tokens.json 中记录对应的风格值。整条视频保持同一套色板、字体和组件语言，不自动混用。

### 深海军蓝科技风（navy-tech）

适合 AI 工具、软件操作、自动化流程、数据和科技观点。

- 画幅优先 16:9 横屏；默认画布为 1920×1080
- 深海军蓝背景和面板，青蓝用于结构线、路径和高光
- 粉色用于关键词和重点动作，黄色只做少量强调
- 左侧放中文大标题，位置偏上但避开人物脸部和字幕；右侧用 UI、流程、数据、浏览器或卡片解释内容
- 标题滑入，UI 分层展开，数据平滑滚动，卡片翻页，进度逐步增长
- 转场使用 ease-out、ease-in-out 或轻微 spring，回弹要有减速和余韵，不做硬碰撞
- 人物口播区域保持干净；必要时把人物缩小为圆形画中画，避免挡脸
- 全片只保留一条细的不透明顶部进度条，不画红线，不为每一个段落单独加横线

### 奶油拼贴信息图风（cream-collage）

适合内容创作、方法拆解、工作流说明、步骤卡、编辑工作台和产品发布信息图。它是轻量的纸张拼贴系统，不是大面积深色 UI。

#### 色彩与字体

- 透明底叠加优先；必须有底色时使用奶油白 #F7F0E5
- 主文字使用深咖啡 #3B352F
- 主要强调色：珊瑚橙 #E58B76、鼠尾草绿 #A9B8A0、柔雾粉 #D99A9B、奶油黄 #E9C875
- 禁用深蓝、纯黑大底、厚重黑色大盒子和强烈霓虹渐变
- 中文字体使用思源黑体 / Source Han Sans SC；常规或中等字重，不默认加粗
- 文字使用柔和投影增强可读性，不使用黑色底条

#### 构图与动效

- 左侧放大字，承担一个清晰的核心结论；中间留出人物口播区，不能挡脸、嘴部或字幕
- 右侧只放 2–3 个小卡片、缩略图、标签、时间轴或纸张图形，不使用巨大面板
- 卡片使用奶油白或低饱和色块、细深咖啡描边、约 14–18px 圆角和轻微纸张阴影
- 长文案按语义拆成 2–4 个画面；每个画面只保留一个大关键词和一条短辅助说明
- 小字拆成两行，避免一整行横向穿过人物区域
- 大字从左侧轻微滑入；卡片错开 0.12–0.20 秒依次下落、回弹或弹出
- 时间轴和数字可以从 0% 平滑增长到目标值；结尾保留约 0.5 秒方便衔接
- 画面切换用短暂淡出、横向擦拭、卡片滑移或同色纸张延展，不使用突然黑场

## 如何选择风格

在调用时直接写出风格名或关键词：

| 调用关键词 | 采用风格 | 适合内容 |
| --- | --- | --- |
| navy-tech | 深海军蓝科技风 | AI 工具、软件、流程、数据、科技讲解 |
| 蓝色风格 | 深海军蓝科技风 | 蓝色科技感、产品操作、自动化 |
| 深蓝科技风 | 深海军蓝科技风 | 科技观点、软件界面、工作流 |
| 科技感 / AI 工具风 | 深海军蓝科技风 | 默认科技包装系统 |
| cream-collage | 奶油拼贴信息图风 | 内容创作、步骤拆解、方法论 |
| 奶油风 | 奶油拼贴信息图风 | 浅色卡片、纸张拼贴、轻量信息图 |
| 奶油拼贴 | 奶油拼贴信息图风 | 杂志排版感、工作流说明 |
| 浅色卡片 / 杂志排版感 | 奶油拼贴信息图风 | 轻量卡片、标签和纸张图形 |

未指定风格时默认使用 navy-tech。用户提供参考图或参考视频时，以参考内容为最高优先级，先判断它更接近哪套系统，再让整条视频保持一套主色板和组件语言。若用户明确指定风格，则本次指定覆盖默认值。

可直接复制的调用示例：

~~~text
请使用 full-video-motion-workflow，采用奶油拼贴风，读取我提供的素材，完成整条视频的分镜、动效、转场、音效和 ChatCut 组装。保留已有字幕，人物口播区域保持干净，不要导出。
~~~

深蓝科技风示例：

~~~text
请使用 full-video-motion-workflow，采用 navy-tech 深海军蓝科技风，读取当前 ChatCut 项目里的素材，先分析整条口播，再制作分镜、透明动效、转场和数据动画，最后组装成可编辑时间线。
~~~

## 完整执行流程

### 1. 盘点项目与素材

读取当前 ChatCut 项目和活动时间线，确认画布、帧率、总时长、视频轨和音频轨。把素材区分为 A-roll、B-roll、图片、Motion Graphics、字幕、音效和 BGM，并检查人物视频是否已有声音、字幕是否已经存在、是否有可复用的 Logo、卡片、数字、画中画和转场。

用户已有字幕时保留字幕并禁止重复生成；已有配音时保留原配音和内容顺序；已有 BGM 时只调整它的音量，不擅自换曲。优先使用当前打开的项目，不改动其他项目或旧版本素材。

### 2. 先理解整条口播，再建分镜

先完整理解内容，再按观众理解任务、画面变化和动作节奏拆分视觉段落，而不是平均分配成一句口播配一个静态画面。每个段落写明：

- 对应口播、语义目的和 sceneId
- A-roll、B-roll、透明叠加、画中画、UI 卡片或 CTA 类型
- 进入动作、主体运动、关键词 cue、稳定态和退出动作
- 与前后段落的运动承接、转场长度和转场素材
- 标题、卡片、数字、Logo 的位置、大小和层级
- 人物安全区、字幕安全区和顶部进度条状态
- 音效种类、准确锚点、尾音和 BGM 音量

建议保存 scene-plan.json 和人类可读的 STORYBOARD.md，确保后续调整仍然可追溯。

### 3. 分工制作动态素材

- HyperFrames：网页、产品操作、鼠标、滚动、翻页、按钮、流程、浏览器感 UI 和交互演示
- Remotion：全局进度条、标题系统、数字滚动、人物圆形画中画变换、跨镜头时间编排、批量组件和自定义转场
- ChatCut：导入、排列、缩放、裁剪、轨道管理、已有字幕、BGM、音效、人声处理、预览和最终导出

叠加到人物上的效果优先导出透明 WebM VP8/VP9 或 ProRes 4444。普通 H.264 / MP4 的黑色背景不等于透明，放入 ChatCut 前必须确认 Alpha 通道真实存在。全屏不透明 B-roll 才使用普通 MP4。

效果按功能拆成独立素材：全局进度条、标题、关键词、数字计数器、功能卡片、Logo 下落回弹、人物圆形画中画和转场。不要把所有动效合并为一个无法单独调节的大视频。用户提供官方 Logo 或参考图时优先使用原始图像资产，不凭记忆重画。

### 4. 设计转场

每个相邻视觉段落都要有转场策略，并继承前段的运动方向或形状：左右平移接左右平移，推近接局部放大或 UI 展开，卡片出现接翻页，数据滚动接图表变化，人物全屏接圆形缩小。默认转场长度 6–12 帧，使用 ease-out、ease-in-out 或轻微 spring。

需要真实剪辑边界时，在 ChatCut 使用 transition；需要自定义图形运动时，单独输出透明转场素材。不要用黑色全屏层伪装转场。

### 5. 组装到 ChatCut

主人物口播放在主视频轨，全屏 B-roll 放在替换画面轨，透明标题、卡片、数字和装饰放在独立上层轨，进度条放在最高的全局包装轨。人物画中画使用圆形遮罩和安全边距，避开脸部、字幕和核心内容。音效、BGM 和人声保持分轨。

先导入并核对全部素材，再根据 scene-plan.json 和 chatcut-import-plan.json 放置。素材放错、出现黑底、乱码、文字重叠或挡脸时，只修对应素材，不重做整条时间线。

### 6. 音频规则

人声加强或语音隔离只作用于含有人声的素材，不作用于 BGM、环境声和音效。BGM 放在独立轨道，先从约 -30 dB 作为人声下的起点，再按试听微调，不能盖住口播。

音效服务于主要动作，不是每出现一个东西就响一次：Mouse Click 只用于真实的页面切换、翻页或主要视觉段落切换；whoosh 用于明确的平移或翻页；pop 用于卡片弹出；impact 只用于少量重点强调。音效之间留出尾音，不延长视频时长，也不让多个音效拥挤在同一瞬间。

### 7. 逐镜头验收

至少检查每个镜头的首帧、进入 cue 前后、主体稳定态、转场中段、末帧和下一镜头。重点确认：

- 动效透明区域确实透明，未混入黑底
- 人物脸部、嘴部、字幕和主要动作没有被覆盖
- 大字没有乱码、重叠、裁切和错误换行
- 左侧大字与中间人物区域留有安全空间；奶油风小字通常为两行
- 顶部只有一条细的不透明进度条，不是红线，也不是每段一条横线
- 卡片尺寸、画中画圆形大小和位置在不同镜头之间稳定
- 转场自然，没有突然黑帧、方向冲突或生硬回弹
- 人声清楚，BGM 不盖人声，音效只出现在必要的动作点
- 原有字幕、轨道、时长和间隙没有意外变化

必须结合 ChatCut 实际 viewer 画面验证，不能只根据“导入成功”或工具返回成功就宣布完成。

## 推荐保留的复用资料

完成一条视频后，保留这些文件，下一次可以直接复用流程和视觉规范：

- scene-plan.json：按视觉段落记录的分镜
- STORYBOARD.md：人类可读的分镜与动作说明
- style-tokens.json：本次选用的 navy-tech 或 cream-collage 以及色板、字体、阴影和间距
- asset-manifest.json：素材来源、用途、透明性和尺寸
- chatcut-import-plan.json：轨道、位置、时长和叠加关系
- audio-plan.json：BGM、人声和音效的锚点、音量与尾音
- qa-report.md：逐镜头验收结果与已修问题
- HyperFrames / Remotion 源文件及透明输出文件

## 默认原则

没有特别说明时：使用 navy-tech；默认 16:9 横屏；以人物口播为主线；透明动效优先；保留已有字幕和原配音；顶部只保留一条细进度条；音效只服务主要切换和动作；完成 ChatCut 可编辑时间线后再等待用户验收。只有用户明确说“导出”或“保存到桌面”时才导出文件并交付。
