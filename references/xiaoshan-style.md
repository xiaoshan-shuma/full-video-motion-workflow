# 小珊深蓝科技讲解风

这份规范来自用户提供的四张参考图，用作默认视觉系统。它描述的是视觉语言，不是要求复制参考图里的软件界面。

## 色彩层级

- 主背景：深海军蓝，接近 `#071326`、`#0B1B35`。
- 深色面板：`#102443`、`#132B4F`。
- 结构蓝：`#1D5D9B`、`#287FBE`。
- 高光青蓝：`#35D6F2`、`#71E7F5`。
- 重点粉：`#FF5AAB`、`#F03F91`。
- 少量黄色：`#F4D34F`、`#F6C84A`。
- 主文字：`#F2F6FF`。
- 次文字：`#91A8C8`。
- 细边框：使用低透明度青蓝或灰蓝，不使用纯红线。

颜色使用比例：深蓝负责 60–75% 画面，白色/浅蓝负责信息主体，青蓝负责结构和路径，粉色负责关键词和动作，黄色只负责少量第二重点。不要同时大面积使用粉、黄、青三种高饱和色。

## 版式

- 顶部：一个窄而清晰的全局章节导航/进度条。底轨不透明，激活段更亮；不要在每个镜头上方额外画线。
- 左侧：大号中文叙事标题，允许关键词用粉色或黄色突出；标题必须有足够对比度和描边。
- 右侧：深蓝 UI 面板、流程卡、数据卡、时间线、对话框或产品界面。
- 人物：人物作为真实主体，不被装饰覆盖；需要讲解时使用圆形画中画，带轻微边框和柔和阴影。
- 底部：为用户已有字幕保留稳定安全带，动效不要进入字幕区。

## 图形语言

- 面板以方角或轻微圆角为主，边角不超过 8px。
- 使用细边框、内层线、状态标签、小型系统文字、时间线色块和局部高光。
- 可以使用克制的蓝色光晕，但不能用大面积发光球、装饰性气泡或遮挡主体的光斑。
- 产品/Logo 以用户提供的官方图像为准，不凭记忆绘制替代品。

## 动效语言

- 标题：从侧面轻微平移 + 淡入 + 关键词强调。
- 卡片：错峰出现、轻微上移或下落、短暂回弹，最后保持稳定。
- 数据：平滑滚动到目标值，目标值停留足够时间，不快速抖动。
- UI：鼠标/光标、滚动、翻页、按钮状态和时间线进度要有连续运动。
- 人物：从全屏平滑缩放到圆形画中画，使用圆形遮罩的同步 reveal，不能突然裁成圆形。
- 转场：通常 6–12 帧，前后方向一致；避免硬闪、黑场、过度弹跳和无意义的扫描线。

## 文字规则

- 中文优先，英文只做辅助。
- 大字可以醒目，但不能压住脸和字幕。
- 重点字优先使用粉色，第二重点使用黄色，普通信息使用白色/浅蓝。
- 所有文字在导入 ChatCut 前完成字体、描边、行数和安全区检查。

## 参考视频风格补充

以下规则来自对一条约 2 分 10 秒横屏口播成片的完整拆解。它们用于补充默认视觉节奏，不要求照抄参考视频中的具体文案或软件界面。

这类视频的核心不是高频切镜，而是“真人建立信任，图形解释逻辑”：

- 真人口播承担亲和力、可信度和情绪。
- 深蓝科技信息图承担流程、数字、选择和结果的解释。
- 镜头切换可以克制，但画面内部必须持续发生有意义的状态变化。
- 每个视觉段落围绕一个观众任务组织，不按每句话机械切换。
- 常用节奏为：结论出现 → 图形隐喻建立 → 状态发生变化 → 留出阅读时间 → 顺势进入下一章节。

整条视频可参考以下宏观节奏：

1. 开场钩子：真人全屏建立主题，快速出现产品、提示词或自动剪辑结果。
2. 方法价值：人物与 UI 信息图交替，展示工具不是“魔法按钮”，而是一套工作流。
3. 痛点堆积：用任务卡、清单或空白时间线表现重复劳动和认知负担。
4. 方法展开：按素材、文案、规则、检查等步骤逐个点亮流程节点。
5. 生成与复核：展示第一版、待复核、人工选择和继续迭代的状态变化。
6. 人机分工：使用百分比、滑杆或决策结构说明 AI 执行与人工判断的边界。
7. 收尾 CTA：减少信息量，恢复人物主体，最后把人物平滑缩至角落圆形画中画。

## 两种画面模式

### 模式 A：真人主导

用于钩子、观点、转折、个人判断和 CTA：

- 真人保持全屏或占据主要画面。
- 只在人物身旁放一个主要标题、数字或小型图形提示。
- 不用大面板压过人物，不在脸部和手势路径上放装饰。
- 适合出现“我认为”“真正有用的是”“最后必须自己判断”等主观表达。

### 模式 B：信息图主导

用于流程、步骤、对比、数据和软件操作：

- 背景切换为深海军蓝信息图空间。
- 大标题放在左上或左中，并整体偏上，为下方人物窗口和字幕留空间。
- 右侧只保留一个主要视觉隐喻，不堆叠多个同权重面板。
- 真人可缩为左下角圆角窗口；收尾身份 CTA 可缩为右下角圆形头像。
- 从真人全屏进入该模式时，人物缩放、遮罩变化和信息面板出现必须同步完成。

同一章节内尽量保持模式稳定。只有叙事角色发生变化时才切换模式，避免频繁把人物放大又缩小。

## 语义到视觉的映射

根据口播含义选择视觉机制，不把所有句子都处理成标题卡：

| 口播语义 | 首选视觉机制 | 推荐状态变化 |
| --- | --- | --- |
| 工具、平台或产品名 | 用户提供的官方 Logo、产品界面 | Logo 落位、界面展开、轻微推近 |
| 输入提示词或下达任务 | Prompt 输入框、光标、按钮 | 逐字输入、提交、状态切换 |
| 自动完成或生成结果 | 时间线、任务卡、结果卡 | 扫描、填充、原始卡变结果卡 |
| 步骤和工作流 | 节点链、编号卡、路线图 | 节点依次点亮、路径连通 |
| 重复劳动或任务堆积 | 待办清单、堆叠卡片、空白时间线 | 卡片累积、勾选、空白被填充 |
| 数据、播放量、涨粉 | 大数字、计数器、简洁图表 | 数字滚动到目标值后稳定停留 |
| AI 与人的职责比例 | 百分比圆环、分区滑杆、双列职责卡 | 圆环绘制、滑杆移动、区域高亮 |
| 选择、审美和过审 | 决策分支、人工审核印章、待复核状态 | 分支收束、印章落下、状态变更 |
| 第一版与继续迭代 | V1/V2 版本卡、修改记录 | 版本替换、旧状态淡出、新状态接管 |
| 方法总结或结尾 CTA | 极简标题、人物主体、关注提示 | 信息收束、人物回归或缩至圆形 |

一个段落只选择一个主要隐喻。若右侧已经用时间线解释“自动剪辑”，不要同时再放浏览器、流程图和大量装饰图标。

## 动效和转场语法

### 动效结构

每个视觉段落至少包含四个阶段：

1. **进入**：8–14 帧内完成淡入、短距离平移或遮罩揭示。
2. **建立**：标题或主图形先出现，辅助卡片错峰跟随。
3. **变化**：发生一次与口播含义对应的状态变化，例如输入、填充、勾选、滚动、扫描或版本替换。
4. **停留与退出**：结果至少稳定停留约 0.6–1.2 秒，再用 6–12 帧退出或承接下一段。

动作应使用平滑减速和连续速度曲线。轻微 spring 只用于卡片落位或 Logo 下落，回弹幅度逐次衰减；禁止突然改变方向、连续大幅弹跳或硬碰撞式停下。

### 统一运动方向

- 一章内的卡片统一从同一侧进入。
- 流程默认从左向右，列表默认从上向下。
- 前一镜头向左推出时，下一镜头也应沿同一方向接入。
- 推近后的下一镜头优先接局部展开，不突然反向缩远。
- 章节变化可用短淡切、同向版式替换、遮罩淡入或深蓝呼吸空场。

### 转场选择

- 同类信息更新：原位内容替换或交叉淡化。
- 章节推进：整组元素同向滑出，下一组沿同向进入。
- 软件操作：鼠标动作、页面滚动或面板展开作为转场本身。
- 数据结论：数字停稳后由同色线条或色块延展到下一画面。
- 真人转信息图：人物缩小，同时主面板展开，避免先黑场再出现。
- 信息图转 CTA：卡片淡出，人物放大或移至右下角圆形窗口。

避免矩形光框横扫、廉价扫描线、随机旋转、闪白、黑场和无语义装饰。动效强度应随内容层级变化，普通说明不使用和开场钩子同等级的冲击动作。

## 人物、字幕和安全区

- 先检查人物脸、身体、双手动作和已有字幕的位置，再确定动效坐标。
- 大标题优先放在人物对侧，并保持偏上；人物下方需要画中画时，不把文字压到该区域。
- 圆形人物窗口必须经过“缩放 + 位移 + 圆形遮罩渐变”连续完成，不能瞬间裁成圆形。
- 左下角画中画适合教程主体；右下角圆形头像适合结尾身份和关注 CTA。
- 画中画大小、边框和阴影在相邻镜头中保持稳定，不无故跳动。
- 底部已有字幕区域视为禁入带。除非用户明确要求修改字幕，否则不新增、替换或覆盖字幕。
- 顶部进度条占用独立安全带。标题与卡片不能贴住进度条，也不能为每段再增加一条装饰横线。

## 可复用制作顺序

1. 完整观看并转写整条 A-roll，标记钩子、观点、流程、数据、人工判断和 CTA。
2. 先划分视觉段落，再在段落内部标记关键词 cue；不要先生成零散小动效。
3. 为每段确定真人主导或信息图主导，并锁定人物、字幕、进度条安全区。
4. 为每段只选一个主要视觉隐喻，写明进入、状态变化、停留和退出。
5. 先完成全局视觉系统：色板、字体层级、标题坐标、面板样式、人物画中画尺寸和进度条。
6. 用 HyperFrames 制作网页交互、Prompt、滚动、翻页和 UI 状态动效；用 Remotion 制作标题、计数器、人物变形、全局时间编排和自定义转场。
7. 每个标题、Logo、计数器、卡片和转场分别输出，先验证 Alpha、尺寸、帧率和时长。
8. 导入 ChatCut 后先放 A-roll、已有字幕和人物画中画，再放主信息图、独立动效、全局进度条。
9. 全部画面确认后再添加少量音效和 BGM；Mouse Click 只服务主要翻页、提交和关键状态变化。
10. 逐镜头检查首帧、动作中段、稳定帧、退出帧和下一镜头，修正单个素材，不重做已确认部分。

## 质量验收

交付前必须满足：

- 观众关闭声音时，仍能通过人物、标题和图形变化理解每个段落的核心意思。
- 观众开启声音时，视觉动作跟随口播关键词，不提前泄露结果，也不拖到口播结束后才出现。
- 每段只有一个清晰主视觉，信息层级能在一秒内辨认。
- 左侧大标题在不同视频和不同镜头中保持统一高度基线，通常偏上放置。
- 人物脸、手势、字幕和顶部进度条均未被其他元素遮挡。
- 所有透明素材在浅色和深色检查底图上均无黑底、黑边或异常半透明。
- 数字滚动最终准确停在目标值，停留时间足够阅读。
- 相邻镜头的运动方向、速度和颜色有承接，没有突兀黑帧或硬切。
- 动效可在 ChatCut 中独立调整位置、大小、时长和删除，不依赖一个合并的大视频。
- 音效数量克制，BGM 不盖人声，已有字幕没有被重复生成。
